# 放蛋实时推荐模型

每轮的配额为 `r_i`，总数为 `T = Σ r_i`。按实际记录求数量 `c_i`，完成轮数
`q = min floor(c_i/r_i)`，本轮进度 `p_i = min(r_i, c_i-q*r_i)`。
只有 `p_i < r_i` 的物品可以被推荐。超前数量保留，不能挤占当前轮的缺项。

使用带配额约束的最大熵加权抽样，而不是按虚拟出场时刻排队。
每步对尚有配额的候选计算 `log w_i = log(剩余配额_i) + 1.1×进度差额_i
− 连出代价_i − 扎堆代价_i − 后续被迫连出代价_i`。
用独立 Gumbel 扰动选取最大分数，等价于按 `w_i / Σw` 抽样，所以不只在同分时随机。

理想间隔为 `P_i = T/r_i`，优先保留至少 `floor(0.65×P_i)` 次拿取的间隔，跨轮保留历史。
当剩余位置已经不足以继续推迟某物品时，优先安排它，给同种物品的下一次出场留空间。
占比不过半且仍可无连出地完成时，保留这种可能；过半占比采用软代价，允许少量连出。
这样避免把 5:3:1 等比例强行锁进 A-B-A-C-A-B-A-B-A 一类固定交替。A B A B
有合适的第三项时会优先打散，已超前的稀有项不会为了打散被过早耗完。

随机数来自 Web Crypto `getRandomValues`，不使用固定轮次种子或重复的出场表。
当前建议在页面重绘时保持稳定，只有实际记录、比例变化或用户主动换一个时才改变。
实际拿了其他物品，也会重新计算。经过几秒不改变推荐，时间不是抽样权重的输入。
跨轮保留实际放置历史，稀有项的间隔不会清零。
手动设数不是实际出场，不把批量设数伪造成连续放置历史。

数量精确是硬约束。随机抽样允许偶然得到同一建议，不承诺每次重算结果都不同。
间隔、避免重复和随机性是尽量满足的目标；高占比、手动拿取、
大量超前或某些配额已经耗尽时，无法同时严格满足所有目标。

安全边界：这是工作人员使用的客户端推荐器，不是防作弊的服务器抽奖系统。
即使随机数不可预测，公开的每轮配额及已出数量仍会泄露轮尾剩余奖品；客户端逻辑
也能被查看和修改。若需要防玩家读取或操纵，应另行设计由服务器持有秘密状态、
校验权限并记录抽取结果的方案。严格配额本身造成的轮尾推断仍然存在。
