# Admin reset of today's angel room

The admin detail sheet for today's angel daily room contains 清零天使大群. No personal account, custom group, devil room or previous day's angel room is eligible. The administrator must type the exact confirmation text after reviewing the current group. Both administrator slots can perform the operation; their audit records remain separate.

The reset empties the active sales, stock, placement and independent placement-stock record arrays, zeros inventory breakdown values while keeping their category labels, removes last-placement timestamps and the saved recommendation, and starts a new active segment. Placement returns to round 1. Item IDs/names, proportions, photos, ordering, goals, group membership, private display names, binding settings and saved ID-matching configuration are preserved. Legacy comparison baselines are reset to empty while preserving other configuration.

Before changing the active payload, the same transaction saves the complete previous canonical payload and revision in private admin_team_resets, with the mutation ID and acting administrator slot. This backup is intentionally separate from ordinary closed periods, so today's matching and aggregation do not silently add cleared quantities back in. Backups are not exposed to members or automatically shown as current history. Recovery requires an explicit reviewed operation; this feature does not provide an end-user restore button.

The service-only tally_admin_reset_angel RPC rechecks Beijing date and the room's actual kind, locks the team and compares the expected revision. It advances both placement and dismantle edit revisions, preventing stale clients from restoring pre-reset records. Repeating the same mutation returns a replay acknowledgment without clearing any sales recorded afterward. A different stale reset conflicts and requires reviewing the refreshed data. The admin route requires session, origin, CSRF, UUID/revision validation and the confirmation string. Service credentials stay on the backend. Unknown request outcomes are reported as uncertain and require refreshing, not an automatic second reset.

Validation: synthetic production PostgreSQL BEGIN/ROLLBACK verifies four empty books, first-round empty placement, zero stock subcounts, preserved membership and definitions, exact pre-reset backup, restricted ACLs, devil/stale-target rejection, stale client write rejection and reset retry preserving later sales. 32 Python and 19 Node admin tests pass. Isolated mobile Chrome verifies cancel/wrong text cause no request, correct confirmation zeros the fixture totals, preserves the devil fixture and fits 280–900px detail sheets. Live admin checks only inspect eligibility/button display, cancel the prompt and send invalid-confirmation/no-CSRF requests. No real group is reset during deployment or live verification.
