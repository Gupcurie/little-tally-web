# Item matching, daily display names, and direct dragging

The bottom navigation now has 匹配比对. Every entry starts with the item matching view. Same normalized names and existing explicit aliases are preconnected. Users can select multiple sales items and multiple placement items, connect them, disconnect a group, or explicitly mark an item for independent comparison. Every item must be handled before confirming and viewing today's quantity differences and candidate time intervals. Independent items still count as differences; they are never ignored. Re-entering the page requires confirmation again. Editing the mapping changes no counts or ledger revision.

Mappings use stable item IDs, so renaming a prize does not break its connection. A new or removed category invalidates the catalog signature and returns the view to setup. Configuration is shared within each team and separate for a personal ledger. Save checks both the current catalog signature and the previous mapping hash; another member's configuration cannot be silently overwritten. Matching reads include only today's sales/placement events, plus today's events from closed segments, without inventory or future recommendation data. Existing inheritance markers are still excluded by the comparison model.

New account sales and inventory defaults: T恤、红娃衣、黑娃衣、扑克、拼图、磁吸支架、掼蛋、便利贴、冰箱贴、盆栽、鼠标垫. New placement defaults: 鼠标垫、盆栽、便利贴、冰箱贴、拼图、扑克、掼蛋、娃衣、磁吸支架、T恤. Existing personal rows are untouched. Daily-room preset initialization replaces only empty dismantle books and never imports personal quantities into a room.

Daily placement membership stores private canonical-ID-to-label maps. All members share canonical quantities and IDs; each placement member sees their prior names. Exact identities/names and a small explicit synonym dictionary (支架/磁吸支架, 扑克牌/扑克, 掼蛋纸牌/掼蛋) establish shared identities. Ambiguous unfamiliar names are not guessed into an existing prize: they become zero-count shared categories. Existing categories remain visible, so counts cannot disappear. If a private label would collide with another shared category, the extra category gets a display-only 群 suffix. Canonical names remain available to the admin. A placement rename changes only that member's label; category deletion, ratios, counts and ordering still operate on the shared group book. Each member's optional placement inventory remains a projection of the shared independent placementStock book.

Database migration 20261113175224_matching_presets_member_labels.sql preserves the previous daily role checks, per-role revisions and mutation replay protection via revoked private role_join_v1/role_save_v1 helpers. New matching_configs and membership fields have RLS and no direct client table grants. Public RPCs authorize auth.uid() against membership/ownership. Matching saves lock the same ledger scope as data saves. Personal configurations cascade when the synthetic/test owner is deleted; team configurations cascade with the team.

Dragging now defers DOM replacement during both pending holds and active movement. Pointer movement/release is tracked on the window; capture begins only after activation so short taps retain their native target. The final reorder waits for an in-flight save, verifies the account/team/page/book context, then changes only item order in the latest state. Touch tremor allowance is 16px, activation 420ms. Cancellation restores the prior order. Resize redraws matching wires.

No real room was joined by live browser QA.

Deployment must back up code and the database, validate hashes against the matching-presets-baseline, apply schema before frontend modules, and update the service worker last. Do not restore the pre-daily unguarded database helpers. A schema rollback requires a reviewed forward migration: the new public wrappers and projections depend on membership label columns. Restoring an old full database dump would overwrite subsequent business changes and is not a routine rollback.
