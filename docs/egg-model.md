# 放蛋推荐与超出数量（2026-11-01）

卡牌、物品详情、比例和统计都跟随整体轮次。整体已完成轮数为所有物品 `floor(累计数量 / 比例)` 的最小值。本轮数量是累计数量减去已完成轮数对应的数量，不在单个物品满额时归零。例如比例 6 的物品累计 7 个、其他物品未满时显示 `7/6`；整体进入第二轮后显示 `1/6`。主条最多满格；黄色副条表示超出量相对于一个配额的进度，超过一个配额时封顶，完整超出量保留在文字描述中。

推荐从实际记录和当前数量计算剩余配额，超出的物品不再占用本轮推荐名额。新版账号计划使用版本 2，版本 1 仍可读取；前台刷新会生成并同步新版计划。没有修改原始记录或数据库表结构。

## 整轮选择

- 数量、配额和已经发生的历史固定，候选顺序不会修改它们。
- 小规模（最多 10 个剩余物品，排列数不超过 10,000）枚举排列；其余情况使用多份随机候选、交换和打乱候选。
- 整体评价相邻重复、低占比物品的过短间隔、ABAB 和间隔短缺。只惩罚过密，不要求每次严格等距，不固定稀有物品的位置。
- 先保护非高占比物品不连出，再尽量减少整体连出和稀有物品挨近；在接近最佳间隔质量的集合中随机选取。
- 人工点击“重新生成本轮顺序”时，对比原名单的位置、相邻搭配以及最长公共子序列，优先在差异较大的合格候选中随机选择。某物品占比超过一半时，显式重排允许至多增加一次该高占比物品的连出，以释放小配额下的变化空间；不会因此增加其他物品的连出。
- 可用方案很少时提示本次变化较小，不虚构能够同时满足所有要求的新顺序。此算法除小规模枚举之外属于候选搜索，不承诺找到所有可行排列或全局最优。

## 不同低占比物品之间的间隔（2026-11-01 补充）

不只同一物品，多个低占比品类也作为一组计算间隔。当前低占比组取配额不超过最高配额的一半、低于所有品类平均配额、单品占比不超过25%的品类，至少两类才启用。判断始终使用配置比例，不因某一物品暂时剩得少而把它变成低占比物品；等比例品类不会全部被当作低占比组。

单步推荐参考最近任何一种低占比物品的实际放入位置，用低占比组总占比计算共同间隔目标（总配额/组配额），优先在它们之间穿插其他品类，并为轮尾保留可用的分隔品类。共同冷却距离为目标距离的65%向下取整，至少2个拿取位置；这是有条件的偏好，不是必须等距的固定周期。ABAB打断偏好不再提前消耗尚在共同冷却中的低占比物品。

整轮候选在原先的连出限制后优先减少低占比组相邻、共同间隔过短，再考虑各自稀有间隔和整体间隔代价，最终仍从合格方案中随机选择。新增整段轮换候选，重新评分历史边界，增加在保持间隔时改变稀有位置的机会。跨轮继承实际历史，拿了非推荐物品后也重新计算。轮尾只剩低占比品类、手动指定第一件或配额限制导致无法完全分隔时，按剩余配额完成，不丢品类、不虚构分隔物品，不承诺所有组合都能完全隔开。

计划格式仍为version 2，新计划在context中标记rareSpacing=1。用户端刷新读取无此标记的旧计划时仅重建推荐并同步，不改实际数量或记录；后台仍只读用户端同步的同一份计划。旧计划的已存顺序和超出512个存储前缀后的旧随机流仍可还原，新计划前缀后的流使用新规则。

## 保存与继续

每份计划仍使用独立 Web Crypto 随机种子。保存最多 512 个已选顺序及当前模拟上下文，剩余超大轮次按同一数量/历史模型继续生成，避免将数百万个编号写进账号账本。按推荐实际放入时，在同一次云端保存中推进当前计划；拿了别的物品、减回、改数或改比例时重新计算。

后台只读同一份账号计划，使用相同 core.js 还原名单，不另抽一份随机顺序。前后台都需刷新加载新版脚本。人工重排主动参考上份名单，因此相邻两次重排是有意相关的；随机种子独立不等于强制重排后的顺序彼此独立。
