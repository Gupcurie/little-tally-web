# 销售与库存绑定

设置中的开关默认关闭，保存在当前账号的完整账本内；本机模式保存在当前浏览器。开启不会回算旧销量或改动现有库存。只从开启后新增的销量变化开始联动。

- 销售加一，绑定库存减一；销售减一，绑定库存加一。手动修正累计销量也按修正差额联动。
- **库存加减、入库、盘点和调整分项不产生销售。** 这是用户更正后明确选择的规则，不能改成双向销售。
- 默认按同名品类匹配，可手动改对应库存及扣减分项。绑定按品类 ID 保存，改名不会换绑。没有对应品类时拒绝销售，不默默漏扣库存。
- 默认扣未分类库存。有已拆、未拆等分项时，可指定分项；不够时不自动改扣其他分项。销量与库存、分项和成对记录一起提交，要么全部保存，要么全不保存。
- 关闭后后续记数独立。删除已联动的销售记录属于撤销该笔交易，会同时撤销原库存变动，包含原分项；库存中的销售联动记录需回销售历史撤销。不能让库存侧删记录反过来改销量。
- 删除整个品类保留另一账本已有数量，只解除历史关联。单独导入一个账本建立新基准，不回放历史销售，不改变另一本数量，并解除旧成对记录关联。完整备份保留绑定设置和成对记录。

`salesStockBinding` 是可选的根设置，含 `enabled` 和按销售 ID 存储的 `pairs`。成对记录共享 `bindingId`；库存侧保留 `bindingPart` 用于撤销。库存分项仍满足其合计不超过总库存的原约束。沿用原 `CloudLedger.commit` / `tally_save` 和本机原子事务，无数据库或权限变更。

销售、库存页顶部均可复制当日销售情况。统计使用北京时间当天的销售账本，分别列出售出、退回、手动改数、净增和各品类累计数，不把库存入库或联动记录重复算成销售。销售页最近一次记数的品类标红，库存页没有红框，也没有推荐绿框。

专项验证覆盖默认关闭、旧销量不回放、销售加减、库存独立、缺货及上限回滚、人工映射、分项、关联撤销、批量撤销、单独导入、多品类共享库存、账号隔离、刷新/重登、日期边界、复制和页面标记。线上只执行合成样例的只读保存校验，没有改真实账号数据。
